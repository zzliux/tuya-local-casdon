# DP 对照表（凯度 GQ Pro）

> 观测方式：设备空闲/运行时用 `tinytuya` 读取 `status()`，配合面板操作逐项比对。
> 「状态」列：✅ 已确认 ｜ ⚠️ 推测 ｜ ❓ 未知

## 基础

| DP | 类型 | 含义 | 观测值 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | bool | 电源 | `false` / `true` | ✅ |
| 2 | bool | 启动/停止 | `false` / `true` | ✅ |
| 7 | int | 设定温度（℃） | `0` / `120` / `190` | ✅ 步进 5 |
| 8 | int | 当前腔体温度（℃） | `19`…`131` | ✅ |
| 9 | int | 预约时间 | `945` | ⚠️ 单位不明（分钟？） |
| 10 | int | 烹饪时长（分钟） | `0` / `1` / `20` | ✅ |
| 11 | int | 剩余时间（分钟） | `0` / `1` | ✅ 到温后才倒数 |
| 13 | bitfield | 故障 + 门状态 | `0` / `256` | ✅ 见下 |

## DP13 位域

| bit | 十进制 | 含义 | 来源 |
| --- | --- | --- | --- |
| 0 | 1 | 腔体超温 | 同族 TD Pro 3 配置 |
| 1 | 2 | 蒸发盘超温 | 同上 |
| 2 | 4 | 腔体低温 | 同上 |
| 3 | 8 | 蒸发盘低温 | 同上 |
| 4 | 16 | 传感器开路 | 同上 |
| 5 | 32 | 传感器短路 | 同上 |
| 6 | 64 | 通讯故障 | 同上 |
| 7 | 128 | 水箱缺水 / 水箱取出 | 同上 |
| **8** | **256** | **门开** | **实测** |

实测证据：开门瞬间 DP13 由 `0` → `256`，关门回落 `0`，其余 DP 无变化。

> ⚠️ bit0–7 的名称来自凯度 TD Pro 3 的上游配置，**未在 GQ Pro 上逐一验证**。你如果触发了真实故障，欢迎把数值记下来提 PR。

## 怎么自己采

```python
import tinytuya, json, time
d = tinytuya.Device('<deviceId>', '<ip>', '<localKey>', version=3.4)
d.set_socketTimeout(8)
last = None
while True:
    dps = d.status().get('dps') or {}
    k = json.dumps(dps, sort_keys=True)
    if k != last:
        print(time.strftime('%H:%M:%S'), k)
        last = k
    time.sleep(1)
```

踩点建议：

1. 先记录**空闲**状态（只有 1/13/102/103/105）
2. 按一下电源（DP1），观察新增
3. 选模式、设温度和时间，观察 7 / 10 / 105 / 106 / 109
4. **启动**，观察 2 / 8 / 9 / 11 / 102 的变化节奏
5. 开门关门，确认 13 的 256
